### 8.1 Epistemic State Machine (`Prismatic.Epistemic.State`)

**Location**: `apps/prismatic/lib/prismatic/epistemic/state.ex`

First-class epistemic state as core system component with finite-state machine transitions.

#### State Space (6 States)

```elixir
@type state :: :unknown | :hypothesis | :supported | :contested | :compromised | :invalid

# State definitions:
# :unknown     - Initial state, no evidence gathered
# :hypothesis  - Working hypothesis formed
# :supported   - Evidence supports the hypothesis
# :contested   - Conflicting evidence exists
# :compromised - Evidence quality is questionable
# :invalid     - Proven incorrect or logically inconsistent
```

#### State Structure

```elixir
defstruct [
  :state,        # Current epistemic state
  :reason,       # Transition reason
  :provenance,   # Origin tracking
  :evidence,     # Supporting evidence list
  :violations,   # Rule violations
  :timestamp,    # State change timestamp
  :confidence    # Confidence score (0.0-1.0)
]
```

#### Transition Rules (Finite-State Machine)

```elixir
# Valid transitions:
# :unknown → :hypothesis | :supported | :invalid
# :hypothesis → :supported | :contested | :compromised | :invalid
# :supported → :contested | :compromised | :invalid
# :contested → :supported | :compromised | :invalid
# :compromised → :invalid (terminal path)
# :invalid → (terminal state - no transitions)
# Self-transitions always allowed
```

#### Key Functions

```elixir
# Create new epistemic state
State.new(:unknown, reason: "Initial investigation")

# Transition with validation
{:ok, new_state} = State.transition(current, :hypothesis, "Evidence gathered")
{:error, {:invalid_transition, from, to}} = State.transition(invalid, :supported, "...")

# Map verdict to state (conservative)
State.from_verdict(:accept, 0.90) # => :supported (high confidence)
State.from_verdict(:accept, 0.70) # => :hypothesis (medium confidence)
State.from_verdict(:reject, _)    # => :invalid
State.from_verdict(:undecidable, _) # => :unknown

# Severity for UI/logging
State.severity(:compromised) # => :critical
State.severity(:contested)   # => :high
State.severity(:unknown)     # => :medium
```

### 8.2 Ignorance Model (`Prismatic.Epistemic.IgnoranceModel`)

**Location**: `apps/prismatic/lib/prismatic/epistemic/ignorance_model.ex`

Explicit ignorance modeling to prevent systems from manufacturing "supported" verdicts.

#### Philosophy

> "Without this, systems tend to produce positive conclusions when they should admit uncertainty."

#### Ignorance Types

```elixir
@type ignorance_type ::
  :insufficient_evidence    # Not enough data
  | :contradictory_evidence # Evidence conflicts
  | :low_confidence         # Below acceptable thresholds
  | :temporal_uncertainty   # Data may be stale
  | :source_unreliability   # Sources cannot be trusted
```

#### Assessment Thresholds

| Condition | Threshold | Result |
|-----------|-----------|--------|
| Evidence count | < 2 sources | `:insufficient_evidence` |
| Confidence | < 0.3 | `:low_confidence` |
| Contradictions | detected | `:contradictory_evidence` |
| Source reliability | > 50% unreliable | `:source_unreliability` |
| Evidence quality | < 0.4 | `:temporal_uncertainty` |

#### Key Functions

```elixir
# Assess whether system should admit ignorance
assessment = IgnoranceModel.assess_ignorance(verdict_data)
# => %{
#   should_be_ignorant: true,
#   ignorance_type: :insufficient_evidence,
#   confidence_in_ignorance: 0.95,
#   reason: "Fewer than 2 evidence sources available",
#   recommended_action: "Gather more evidence before making determination"
# }

# Get ignorance-aware state (prevents false confidence)
IgnoranceModel.ignorance_aware_state(:accept, 0.5, assessment)
# => :unknown (not :supported, because should_be_ignorant)

# Adjust confidence with ignorance penalty
IgnoranceModel.adjusted_confidence(0.8, assessment)
# => 0.5 (capped when ignorant)
```

#### Confidence Penalties

| Ignorance Type | Penalty Factor |
|----------------|----------------|
| `:insufficient_evidence` | 0.7 |
| `:contradictory_evidence` | 0.6 |
| `:low_confidence` | 0.5 |
| `:scope_limitation` | 0.4 |
| `:temporal_uncertainty` | 0.6 |
| `:source_unreliability` | 0.3 |

### 8.5 Assertions (`Prismatic.Epistemic.Assertion`)

**Location**: `apps/prismatic/lib/prismatic/epistemic/assertion.ex`

Claims about reality with full provenance chains.

#### Assertion Contract

Every assertion MUST have:
- `claim` - Statement being made (atom)
- `subject` - Entity the claim is about
- `value` - The claimed value
- `source_id` - Which source produced this
- `artifact_hash` - Hash linking to raw evidence
- `extraction_path` - How the claim was derived
- `confidence` - Float 0.0-1.0 (calculated)

#### Claim Types

```elixir
@type claim_type ::
  :domain_resolves_to_ip
  | :domain_has_mx
  | :domain_has_web_presence
  | :company_exists_in_registry
  | :company_has_legal_form
  | :company_has_statutory_representative

#### Confidence Calculation

```
Final confidence = source_base_confidence × extraction_quality × recency_factor

### 8.6 Conflict Detection (`Prismatic.Epistemic.ConflictDetector`)

|------|-------------|----------|

| `:format` | Same value, different representations | Low |

conflicts = ConflictDetector.detect_conflicts(assertions)

### 8.7 Unified Epistemic Store (`PrismaticNabla.UnifiedEpistemicStore`)

**Location**: `apps/prismatic_nabla/lib/prismatic_nabla/unified_epistemic_store.ex`

Centralized store for epistemic states shared across all reasoning subsystems.

#### Architecture

```
┌─────────────────────────────────────────────────────────┐
│              UnifiedEpistemicStore (GenServer)          │
├─────────────────────────────────────────────────────────┤
│  ETS Table: epistemic_states                            │
│  ├── {state_id, EpistemicState, version, metadata}     │
│  └── {:index, subsystem, [state_ids]}                  │
└─────────────────────────────────────────────────────────┘
      │           │           │           │
      ▼           ▼           ▼           ▼
   NABLA      Prolog       IR/PVM      Lean4
   Levels     KB Bridge    Bridge      Adapter
```

#### Subsystems

```elixir
@type subsystem :: :nabla | :prolog | :ir_pvm | :lean4 | :osint | :custom
```

#### Features

- **Multi-subsystem access** - Thread-safe concurrent access via ETS
- **Event broadcasting** - Phoenix.PubSub integration for state changes
- **State versioning** - Track state evolution with version numbers
- **Snapshot/restore** - Save and restore state checkpoints
- **Cross-subsystem queries** - Query beliefs across all subsystems
- **Conflict resolution** - Handle conflicting updates

#### Key API

```elixir
# Get or create state for session
{:ok, state} = UnifiedEpistemicStore.get_or_create("session-123")

# Update from specific subsystem
{:ok, state} = UnifiedEpistemicStore.update_from_subsystem(
  "session-123",
  :nabla,
  fn state -> add_beliefs(state, beliefs) end
)

# Add beliefs from OSINT subsystem
{:ok, state} = UnifiedEpistemicStore.add_beliefs(
  "session-123",
  :osint,
  [%{content: %{subject: "entity-x"}, confidence: 0.85}]
)

# Record contradiction
{:ok, state} = UnifiedEpistemicStore.record_contradiction(
  "session-123",
  :ir_pvm,
  "belief-a",
  "belief-b"
)

# Create snapshot before risky operation
{:ok, snapshot} = UnifiedEpistemicStore.create_snapshot("session-123", "pre-analysis")

# Restore if needed
{:ok, state} = UnifiedEpistemicStore.restore_snapshot("session-123", "pre-analysis")

# Query beliefs across all states
beliefs = UnifiedEpistemicStore.query_beliefs(
  subject: "entity-x",
  min_confidence: 0.7
)

# Subscribe to state changes
UnifiedEpistemicStore.subscribe("session-123")
# Receive: %{event: :state_updated, subsystem: :nabla, version: 5, ...}
```
